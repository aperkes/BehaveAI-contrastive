BehaveAI contrastive identity vs. idtracker.ai v6
================================================

Recorded: 2026-10-01

Purpose
-------
This note records the important differences between contrastive_identity.py
and idtracker.ai v6. As of 2026-10-01, the default network and contrastive
training loop intentionally follow idtracker.ai much more closely. The older
BehaveAI network remains selectable and old checkpoints remain compatible.


What both systems do
--------------------
* Use continuous track fragments as weak identity supervision.
* Treat images from the same fragment as positive examples.
* Treat images from simultaneous/coexisting fragments as reliable negatives.
* Learn an appearance embedding and cluster it into a known number of animals.
* Use video structure so coexisting fragments cannot receive the same identity.
* Use a complete coexisting group (a "global fragment") to initialize identity
  clusters when one is available.


Current default BehaveAI implementation
----------------------------------------
Network:
* The same torchvision ResNet-18 structure used by idtracker.ai.
* One-channel grayscale input, 96 x 96 pixels by default. RGB input is available
  with --input-color rgb while preserving the same network and training path.
* Direct 8-dimensional, unnormalized embedding with a bias-free final layer.
* Adam optimizer at learning rate 0.001 by default.
* --architecture small-cnn retains the previous RGB model, and checkpoints
  without architecture metadata are recognized as that legacy model.

Training batches and loss:
* BehaveAI motion tracks are split into conservative, contiguous training
  fragments around close encounters, near-tied direct/swapped motion matches,
  abrupt motion changes, and detection gaps. A configurable buffer around each
  ambiguous event is excluded from training.
* Short-gap position interpolation is used only to detect uncertain encounters;
  interpolated points never become crops or join positive fragments. The filter
  is local and does not require all animals to be visible in a frame.
* Builds explicit positive pairs from each eligible fragment and explicit
  negative pairs from coexisting fragments. Nonoverlapping tracks stay unknown.
* Fragments need at least four detections by default.
* Each optimizer step samples 400 negative and 400 positive pairs (1,600 image
  evaluations), matching idtracker.ai. Forward chunks bound peak VRAM without
  changing the effective optimizer batch.
* Uses Euclidean pairwise contrastive loss with the idtracker.ai margin of 10;
  positives are penalized above distance 1 and negatives below the margin.
* Pair probabilities combine fragment size with decaying recent failure counts,
  emphasizing relationships the network still gets wrong.
* Periodically clusters sampled validation embeddings, records silhouette score,
  restores the best model, and stops at the 0.91 target or patience limit.

Crop handling:
* Only crops retained in eligible training fragments are materialized
  sequentially by default. Grayscale uint8 crops require one-third the storage
  of the old RGB crop array. Detections needed only for later full-video
  inference are decoded on demand instead of occupying the training cache.
* Automatic storage uses uint8 RAM when there is enough headroom, otherwise a
  disk-backed NumPy memory map. On-demand video seeking remains optional.
* Median-background masking is optional; unmasked full bounding-box crops are
  also supported.

Clustering and assignment:
* Euclidean K-means operates on the individual crop embeddings retained by the
  conservative fragment filter, rather than on means of the original BehaveAI
  tracks. The legacy model retains cosine K-means.
* Detection embeddings then vote for the identity of each conservative
  fragment. One original BehaveAI track may therefore receive different
  identities on opposite sides of an uncertain crossing instead of propagating
  a mistaken handoff through the entire source track.
* A complete coexisting group of safe fragments initializes and anchors cluster
  identities when all member fragments meet the minimum length. Only the clean
  coexisting portion contributes to each initialization center.
* Fragment probabilities are corrected using coexisting fragments, following
  the basic idtracker.ai P1/P2 idea.
* Fragments are assigned in confidence order while identities already used by
  coexisting fragments are unavailable. A final hard check guarantees that an
  identity appears no more than once in any frame.
* Detections excluded around ambiguous crossings and structurally impossible
  fragments are assigned -1 rather than forcing an identity collision.
* Original unconstrained K-means remains available as a comparison backend.


idtracker.ai v6 implementation
------------------------------
Network:
* ResNet-18.
* Grayscale input.
* Direct 8-dimensional embedding, with no separate projection head.
* Adam optimizer.

Training batches and loss:
* Samples explicit pairs of fragments rather than constructing all relations
  among a group of tracks.
* Default batch contains 400 positive pairs and 400 negative pairs.
* Each pair has two images, so the ResNet processes 1,600 images per optimizer
  step (two forward calls of 800 images each).
* Uses Euclidean pairwise contrastive loss: positives are pulled together and
  negatives are pushed apart to a margin.
* Sampling probabilities adapt using fragment sizes and recent pair losses.
  This emphasizes pairs that the network is still getting wrong.
* Training periodically clusters validation embeddings and measures silhouette
  score. It stops at a target score or after a patience limit.

Clustering and assignment:
* MiniBatchKMeans clusters individual-image embeddings into exactly N animals.
* When possible, centers are initialized from up to 500 images per animal from
  a reference global fragment; otherwise it uses K-means++.
* Image-level cluster frequencies become fragment P1 probabilities.
* Coexisting-fragment evidence produces corrected P2 probabilities.
* Fragments are assigned in descending P2 certainty, updating their neighbors
  after each assignment.
* Ambiguous fragments can remain unidentified.
* Cluster labels are explicitly mapped/reordered into identity labels.
* If contrastive assignment identifies too little of the video, the classical
  iterative accumulation/idCNN protocol takes over using the contrastive result
  as a warm start.


Important current observations
------------------------------
Historical eight-animal test without background subtraction (do not treat its
identity results as reliable: the source manifest was later found to contain
multiple detections with the same track ID in a frame):
* 893 track fragments and 89,582 detections.
* 773 fragments assigned (86.56%).
* 86,439 detections assigned (96.49%).
* Mean assigned confidence: 0.803.
* Zero assigned-identity collisions across 16,811 multi-detection frames.

The zero-collision result verifies structural consistency, but it does not prove
that identities remain correct across track breaks. The algorithm enforces the
collision constraint and excludes -1/unassigned fragments from collision counts.
The main unresolved accuracy question is whether nonoverlapping fragments from
the same animal retain the same identity.


Remaining differences and promising experiments
------------------------------------------------
1. Add visual and quantitative track-break continuity validation.
2. Report per-identity detection/track counts and embedding separation.
3. Compare masked and unmasked crops using the same train/validation split.
4. Compare 8-D, 32-D, and 128-D embeddings; high-dimensional output is useful
   for transfer, but idtracker.ai demonstrates that a compact identity space can
   cluster very effectively.
5. Try image-level MiniBatchKMeans instead of fitting centers only to track means.
6. Add an optional accumulation/refinement stage for confidently assigned tracks.
7. Match idtracker.ai's dedicated validation split more exactly; the current
   silhouette check samples the training crop pool with augmentation disabled.
8. Keep clustering and identity assignment as separate interfaces so K-means,
    GMM, agglomerative, graph-constrained, and unknown-N approaches can be tested
    without changing embedding training.


Interpretation of training output
---------------------------------
* positive_loss: mean penalty for positive-pair distance above 1; lower is better.
* negative_loss: mean penalty for negative-pair distance below 10; lower is better.
* loss: mean pair loss across the balanced positive/negative batch.
* validation silhouette: cluster separation from -1 to 1; higher is better.
These are not accuracies. Final performance should be judged with assignment
coverage, collision checks, continuity across track breaks, visual inspection,
and—when ground truth is available—identity accuracy.

After fixing the tracker to prevent reuse of an already matched track ID, the
video was retracked with frame_skip=0. The corrected manifest contains 357,651
detections across 70,214 populated frames, 4,492 track fragments, and zero
duplicate (video, frame, track_id) keys. A new contrastive run is still needed.
